# EXEC-001 — Founder Daily Brief

**Suite:** Nmood Executive Operating System  
**ID:** EOS-001  
**Status:** Permanent operating system  
**Date:** 2026-07-11  
**Owner:** Nmood Founder  
**Cadence:** Generated every morning, 07:00 GST (Asia/Dubai)

---

## Purpose

Every morning, the Founder sees the state of Nmood in one page — what happened, what's happening, what to watch, and what to decide. The brief is the first thing the Founder reads. It is honest before it is encouraging. No vanity metrics. No spin.

---

## Source Architecture

The Daily Brief is generated by a backend function (`founderDailyBrief`) that runs at 07:00 GST daily via a scheduled automation. It aggregates live data from the platform entities and writes a Brief record (or sends a formatted summary to the Founder). The brief draws from:

- `Member`, `Membership`, `Experience`, `Circle`, `ChatMessage`, `PrivateMessage`, `NotificationReadState`, `SafetyReport`, `SecurityEvent`, `ErrorLog`, `SubsystemHealth`, `AiAuditRecord`, `AuditLog`, `SupportTicket`

No manual input is required. The Founder reads and acts.

---

## 1. Snapshot Metrics

All metrics are computed against the relevant time window and compared to the prior equivalent window (day-over-day, week-over-week, month-over-month).

| Metric | Source | Computation |
|--------|--------|-------------|
| New members | Member entity | Count where created_date in window |
| Active members | Analytics / Member | Members with a session or action in window |
| Premium members | Membership entity | Count where type = premium AND status = active/trial |
| Revenue | Membership / billing | Gross premium revenue in window (net of refunds) |
| AI usage | AiAuditRecord | Invocations in window; by service; blocked/flagged count |
| Experiences created | Experience entity | Count where created_date in window |
| Circles created | Circle entity | Count where created_date in window |
| Messages | ChatMessage + PrivateMessage | Count in window |
| Notifications | NotificationReadState | Sent in window; read rate |
| Reports | SafetyReport | Opened in window; resolved in window; open count |
| Safety incidents | SecurityEvent | Count by risk_level (medium/high/critical) |
| Bugs | ErrorLog | New in window; severity distribution; P0/P1 open count |
| Platform health | SubsystemHealth | Lowest health_score across subsystems; degraded count |

## 6. Risks (auto-flagged)

The brief flags risks using the Executive Alerts thresholds (EOS-006). Each risk is shown with severity, metric, threshold, and current value.

```
[🔴/🟡] [Risk name]
  Metric: [name] = [value]
  Threshold: [threshold]
  Window: [window]
  Owner: [name]
  First detected: [timestamp]
```

Examples that trigger:
- Server degraded or down
- Crash rate > 1%
- Report spike > 3× rolling average
- Premium failure rate > 5%
- Revenue drop > 20% WoW
- W1 retention < 25%
- AI escalation rate > 2%
- Open P0 bug > 0 for > 12h

## Delivery

- **Format:** Rendered in the Mission Control Founder Brief widget (EOS-003) + optional email to the Founder at 07:00 GST.
- **Archive:** Each brief is stored for trend analysis and the Weekly/Monthly Reviews (EOS-005).
- **Honesty rule:** A metric in the red is shown in the red. The brief never hides a problem to keep the morning cheerful.
